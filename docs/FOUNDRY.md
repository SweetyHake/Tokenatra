# Tokenatra ↔ FoundryVTT: интеграция (v26.4+)

Модуль **tokenatra-connector** запускает студию Tokenatra внутри Foundry VTT
(проверено на v13/v14) и добавляет быстрые действия по актёрам. Само
приложение Tokenatra при этом может быть свёрнуто в системный трей.

## Установка модуля

1. Установите desktop-приложение Tokenatra **26.4+** на машину, где запускается
   клиент Foundry.
2. В Tokenatra: **Настройки → Модель** — выберите модель удаления фона (`.onnx`).
3. Foundry → **Add-on Modules → Install Modules → Manifest URL**:

   ```
   https://raw.githubusercontent.com/SweetyHake/Tokenatra/main/foundry-module/tokenatra-connector/module.json
   ```

4. Включите модуль в мире. Студия открывается из листа актёра (кнопка
   «Tokenatra» в шапке) или контекстного меню актёра.

## Сценарий «Foundry + Tokenatra в трее»

1. Запустите Tokenatra один раз перед сессией.
2. Закройте окно — при включённой настройке «Сворачивать в трей при закрытии»
   (по умолчанию вкл., только Windows) приложение останется в трее.
3. В трее: **«Открыть Tokenatra»** (двойной клик) — показать окно;
   **«Выход»** — завершить приложение.
4. Удаление фона работает прямо из трея — и из окна модуля, и быстрыми
   действиями. Если модель была выгружена по простою, первый запрос
   подождёт её загрузку (~10–30 с) — трей-подсказка и уведомление модуля
   предупреждают об этом заранее.

## Возможности модуля

Запуск студии — по механизму Tokenizer 2: **без глобального хоткея**, редактор
открывается сразу «в режиме редактирования» для выбранного актёра (арт актёра
уже загружен в холст). Синглтон: то же окно для того же актёра поднимается
наверх, выбор другого актёра пересоздаёт редактор. В окне студии — только
вкладка «Создание токена».

| Точка входа | Действие |
|---|---|
| Кнопка «Tokenatra» в шапке листа актёра | Открыть студию с артом этого актёра |
| ПКМ по актёру в директории → «Редактировать в Tokenatra» | То же из контекстного меню |
| Кнопка на панели токенов | Пустая студия (создание с нуля) |
| ПКМ по актёру → «Удалить фон (Tokenatra)» | Вырезать фон арта без открытия студии; обновляется актёр и его токены на сцене |
| Кнопка на Token HUD | То же для выбранного токена |

В студии (embed-режим) вместо системных диалогов сохранения — кнопки
**«В Foundry (с кольцом)» / «В Foundry (без кольца)»**. Диалог после экспорта:
*Создать актёра* / *Обновить текущего* / *Скопировать путь*. Опция
«Применять экспорт сразу» пропускает диалог.

## Настройки

**Tokenatra** (Настройки → Трей и память, только Windows):
- «Сворачивать в трей при закрытии» — вкл/выкл;
- «Выгружать модель в простое» — никогда / 1 / 3 / 5 (по умолчанию) / 10 / 30 мин.

**Модуль** (Configure Game → Manage Modules → Tokenatra Connector):
- адрес Tokenatra (по умолчанию `http://127.0.0.1:7878`; при недоступности
  автоматически пробуется `localhost`);
- папка загрузки для ГМ (`tokenatra/`);
- формат/качество результата (webp/png/jpg);
- «Применять экспорт сразу», «Кнопки на панели и HUD».

## Память: честные цифры

- **Выгрузка модели в трее** — основная экономия: 0,5–2 ГБ ОЗУ (+VRAM у
  DirectML). Модель подгружается лениво при первом запросе.
- **Окно в трее** продолжает держать ~200–400 МБ (WebView + канвасы) —
  это цена мгновенного восстановления; при входе в трей дополнительно
  освобождаются растровые кэши редактора и история отмен сокращается
  до 10 шагов (отменить более старые действия после восстановления нельзя).
- Точность цифр зависит от модели и размера канваса; ориентир —
  Диспетчер задач до/после выгрузки.

## Мультиплеер: доступ для игроков

Студия работает у всех игроков **на любом хостинге мира** — LAN, домен,
The Forge — без настройки сети:

- **Интерфейс студии — живой, из Tokenatra ГМа**: при открытии окна клиент
  ГМа собирает актуальную страницу со своего `localhost:7878` (инлайн CSS/JS
  + транспорт) и передаёт игроку чанками через сокет мира. Игрок всегда
  получает интерфейс версии, совпадающей с запущенным приложением; никакой
  сети до машины ГМа игроку не нужно.
- **Удаление фона выполняется на ПК с Tokenatra** через сокет мира:
  запрос игрока уходит клиенту ГМа, тот выполняет его на своём
  `localhost:7878` и возвращает результат. Транспорт — сам Foundry.

**Умное подключение** (приоритеты, проверяются автоматически у каждого
клиента):

1. **Локальная Tokenatra** — если приложение запущено на устройстве
   игрока, клиент подключается к ней напрямую (своя GPU, свои настройки).
2. **Tokenatra хоста** — если локальной нет, AI-запросы релятся через
   сокет мира клиенту ГМа, тот исполняет их на своём localhost.
3. **Ничего не ответило** — уведомление: «Tokenatra недоступна»
   с подсказкой (запустить у себя / попросить ГМа).

Требования: модуль включён; для приоритета 2 — Tokenatra запущена на
машине ГМа и ГМ находится в мире онлайн. Настройка не нужна — адрес по
умолчанию `127.0.0.1:7878` (менять «Адрес Tokenatra» стоит только если
Tokenatra слушает нестандартный порт).

Замечания:

- Если ГМ вышел из мира, AI-кнопки у игроков сообщат о недоступности релея
  (клиент ГМа — исполнитель, ему нужно быть в мире).
- Картинка на обработку едет через сокет мира (base64) — запрос занимает
  на несколько секунд дольше прямого.
- Тумблер «Разрешить подключения из сети» в Tokenatra для модуля **не
  нужен** — он остаётся для прямых HTTP-сценариев (скрипты/интеграции в LAN).
- Арт с внешних хостингов (S3/CDN без CORS) студия не прочитает —
  сохраните файл локально.
- Игроки без прав загрузки файлов: результат скачивается локально, в мир
  ничего не пишется.

## Архитектура и протокол

```
Foundry (localhost:30000)                 Tokenatra (127.0.0.1:7878)
├─ TokenatraApp (ApplicationV2)           ├─ /?embed=1&origin=…  (iframe, CSP frame-ancestors localhost)
│  └─ iframe ────────────────────────────►├─ tokenEmbed.js (мост, connectorApi 1)
│     postMessage: ready/load/export      ├─ POST /embed_export   (блоб → секретный id)
│     fetch: /health, /process ◄──────────┤─ GET  /embed_export/<id> (CORS, TTL 10 мин)
└─ actions/upload: /process, FilePicker   └─ /health {connectorApi, model_loaded, tray}
```

- **Гвард безопасности** сервера: кросс-сайтовые запросы разрешены только
  для роутов-allowlist (`/health`, `/process`, `/version`, `/device`,
  `/models_list`, `/embed_export*`) и только с Origin localhost-семейства
  (любой порт). Остальные роуты — строго same-origin. DNS-rebinding закрыт
  Host-проверкой.
- **postMessage**: мост активен только при `?embed=1` + валидном
  localhost-origin; модуль фильтрует сообщения по `event.source` и точному
  origin Tokenatra. Никаких `targetOrigin: '*'`.
- **Совместимость**: `/health` содержит `connectorApi`; модуль различает
  «не запущена» / «старая версия» / «нет модели» и подсказывает решение.
  Живой статус — опрос `/health` каждые 8 с; при падении и восстановлении
  Tokenatra iframe перезагружается, контекстный актёр загружается заново.

## FAQ / известные ограничения

- **«Нашёл localhost/127.0.0.1 — что верно?»** — оба; модуль сам пробует
  второй вариант, если первый не ответил.
- **Игроки на других машинах?** См. «Мультиплеер: доступ для игроков» выше —
  сетевой режим Tokenatra + настройки мира модуля (адрес и ключ задаёт ГМ один раз).
- **Foundry открыт по своему домену (https://myfoundry.example)?** Работает через
  сетевой режим (ключ) или `allowed_origins` в config.json; при прокси — добавьте
  location/handle до Tokenatra (примеры выше).
- **Игрок без прав загрузки файлов?** Результат скачивается игроку локально,
  в мир ничего не пишется (уведомление объясняет).
- **Арт с внешнего хостинга (S3/CDN)?** Быстрое действие не сможет его
  прочитать (CORS браузера) — сохраните файл локально и загрузите вручную.
- **Трей только на Windows** (pystray). На macOS/Linux закрытие окна — выход;
  всё остальное (модуль, embed, удаление фона) работает.
- **Модуль предлагает обновление раньше, чем появился zip?** Так бывает,
  если версия в module.json забамплена до релиза; подождите сборку релиза
  или обновитесь позже.

## Разработка: сборка и релиз модуля

- Каталог в репозитории: `foundry-module/tokenatra-connector/`.
- Локальная сборка: `build_module.bat` → `dist/module/tokenatra-connector.zip`
  (корень архива — папка `tokenatra-connector/`).
- **Релизы**: zip собирается CI (`build-release.yml`, job `release`) и
  прикладывается к релизу приложения; `download` в module.json указывает на
  `releases/latest/download/tokenatra-connector.zip`. Отдельных тегов для
  модуля нет — тег `v1.0.0` запустил бы сборку приложения и сломал бы
  `releases/latest`, по которому работает автообновление.
- **Правило**: версию в `module.json` бампить только в релизном коммите
  вместе с тегом `v26.x.y` — манифест на `main` не должен анонсировать zip,
  которого ещё нет.
- Совместимость API моста — поле `connectorApi` (сейчас `1`); при изменении
  протокола повышается и в `/health`, и в `tokenatra:ready`.
